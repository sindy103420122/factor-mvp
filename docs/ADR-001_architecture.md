# ADR-001 架構決策紀錄

- 狀態：草稿（待組員確認）
- 日期：2026-11-05

## 1. 需求摘要（4 句話以內）
研究員設定股票池、因子與成本參數後，系統載入 TEJ 資料並對齊公布日，計算因子與綜合分數。
系統每月選出前 N 檔股票，以扣除手續費、證交稅與滑價後的淨值進行回測。
結果以績效摘要、月度明細與交易紀錄輸出，並與加權報酬指數比較。
同一份資料與設定，任何人執行都必須得到相同結果。

## 2. 問題特徵
| 面向 | 本系統 |
|---|---|
| 系統類型 | 批次分析，非即時 |
| 資料特性 | 日（股價）、月（營收）、季（財報）三種頻率，需對齊可得時點 |
| 複雜度來源 | 多步驟處理，每一步都有前視偏誤的風險 |
| 非功能需求 | 可重現、可稽核、每一步可單獨測試 |
| 專案規模 | 一組學生、8 週、單機執行 |

## 3. 候選架構評估
| 架構 | 符合度 | 理由 |
|---|---|---|
| 管線 | 高 | 資料依序經過 data → factors → portfolio → backtest → report，每段輸入輸出明確，可單獨測試與替換 |
| 分層 | 中 | 適合有介面與資料庫的應用；本系統沒有使用者介面，分層的好處用不到 |
| 微服務 | 低 | 部署與維運成本遠高於收益，單機批次分析不需要 |
| 事件驅動 | 低 | 不需要即時反應行情 |

## 4. 決策
選擇：**管線架構**，各段以「標準化資料格式」銜接。

為何選它：
- 每段只依賴上一段的輸出，Gherkin 情境可以掛在對應段落上（例如公布日對齊掛在 factors、漲停不成交掛在 backtest）。
- 方向 2（智慧調權重）只需要替換 portfolio 段的「因子權重來源」，其他段不動，baseline 與智慧方法的差異就只有這一處，比較才公平。
- 資料來源只在 data 段處理（`app/tej_convert.py`），換資料來源不影響因子與回測。

為何不選其他：
- 微服務：單人或小組作業，拆服務只增加部署成本，沒有擴展需求。
- 分層：本系統沒有前端與交易邏輯，分層架構的優勢用不到。

未來考量：
- 若要接即時下單，可依現有模組邊界把 backtest 換成下單模組，並加入狀態機處理委託狀態。
- 若資料量變大導致回測過慢，可先在 data 段加入快取（parquet），不需改架構。

## 5. 目錄結構
```
app/
  config.py       所有參數；樣本外鎖
  tej_convert.py  TEJ 原始檔 → 標準格式（data 段）
  sample_data.py  假資料產生器（沒有 TEJ 時也能跑）
  data.py         載入標準格式
  universe.py     可交易股票池（US-103）
  factors.py      因子計算與橫斷面標準化（US-101、US-102）
  portfolio.py    綜合分數與選股（方向 2 的替換點）
  backtest.py     成交假設與交易成本（US-104）
  report.py       績效摘要
  runner.py       一行指令串起整條管線
```
